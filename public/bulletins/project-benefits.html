为支持更多优质教育相关工具的开发与成长，SECTL组织现开放新项目加入通道，并为符合条件的项目提供以下扶持与权益。本说明旨在明确合作框架，保障双方权益，推动项目与组织共同发展。

一、加入与申请说明

  • 申请渠道：新项目申请加入组织或申请二级域名，请联系SECTL组织群群主（QQ：3267139343），提交项目基本信息（如名称、定位、功能简介、开源/闭源情况、项目链接等）进行审核；
  • 审核标准：以"服务教育场景"为核心，综合评估项目实用性、稳定性及与组织生态的契合度。

二、内部协作渠道（飞书）

组织为正式成员项目开设飞书内部群组，用于：

  • 项目进度同步与问题讨论；
  • 共享组织内部资料与开发资源；
  • 协作制定宣传与活动计划。

仅限已加入组织的项目核心成员加入，入群方式将在审核通过后由群主（QQ：3267139343）另行通知。

三、核心扶持内容

  1. 专属文档站二级域名支持

    所有正式加入组织的项目，可使用SECTL组织提供的二级域名搭建专属文档站（格式："[项目标识].sectl.top"，如项目名为"SecRandom"，则文档站域名为 "secrandom.sectl.top"）。组织将协助完成域名解析与基础配置，降低项目文档维护成本，提升用户访问便捷性。

  2. 多维度宣传资源倾斜

    组织将通过以下渠道对项目进行阶段性宣传：

    • 官方社群：依托Q群833875216发布项目动态、功能亮点及使用案例；
    • 视频平台：在B站官方账号发布项目介绍、操作演示等视频内容，扩大教育场景用户触达范围；
    • 飞书平台：通过组织飞书官方账号/群组发布项目更新、使用技巧及教育场景应用方案，方便机构与教师群体快速获取信息。

四、开源项目特别约定

对于开源项目，加入组织后需将项目仓库直接移动至SECTL官方GitHub组织下（地址： https://github.com/SECTL），不得采用Fork（复刻）方式。移动完成后，原仓库可设置为镜像或归档，但需保留指向新仓库的跳转说明，确保用户与社区能正确访问最新代码。

五、宣传与长期合作评估

  • 宣传节奏：组织统一宣传固定在每年组织成立周年日开展（具体日期以当年公告为准）；
  • 视频发布规则：在项目处于组织成员期内，无论视频是由组织统一制作，还是由项目独立开发者独立制作的视频，均需通过SECTL组织官方B站账号统一发布；
  • 长期合作评估：除"持续参与满1年"外，需结合项目对教育场景的实际价值（如用户覆盖量、功能迭代质量、社区贡献度等）综合评估，确保合作质量。

六、长期合作激励

针对计划与组织建立长期稳定合作的优质项目，额外设置激励政策：

  • 合作期限要求：自加入之日起，持续参与组织事务且未主动退出满1年；
  • 项目属性要求：需符合组织"服务教育场景"的核心定位（如教学工具、班级管理、学生服务等方向）；
  • 激励形式：根据项目实际贡献度（如用户反馈、功能迭代、社区活跃度等），由组织评估后给予相应奖金支持（具体金额一事一议）。

七、退出机制与后续处理

若项目因特殊原因需中途退出组织，需遵守以下约定：

  1. 提前申请：退出需提前两周提交书面申请至群主（QQ：3267139343）；
  2. 书面申请内容要求：申请需包含以下内容——
    • 项目名称及项目标识；
    • 加入组织的时间；
    • 退出原因说明（可简述）；
    • 项目负责人联系方式（QQ/邮箱）；
    • 确认已知晓并同意退出后的时长清零、信息标注等条款；
  3. 时长清零：退出时，该项目在组织的"持续合作时长"将自动清空，后续重新加入需重新计算合作周期；
  4. 信息标注义务：
    • 项目需在自身仓库的README文件底部注明："本项目曾于XX年XX月至XX年XX月加入SECTL组织，相关信息以组织历史公告为准"；
    • 若为开源项目，还需在README中保留组织归属说明（如"曾隶属于SECTL组织"）；
  5. 历史宣发说明：组织此前发布的B站宣传视频中，若涉及已退出项目，将在该视频评论区置顶说明（如"注：项目[XXX]已于XX年XX月退出SECTL组织，当前状态以项目方最新信息为准"）；
  6. 飞书退出：退出组织后，项目相关成员需同步退出SECTL组织飞书内部群组，不再保留成员身份；
  7. GitHub组织退出：若为开源项目，退出时需将项目仓库从SECTL官方GitHub组织（https://github.com/SECTL）移出，可自行管理或转移至其他账户/组织，原仓库的跳转说明需同步更新或移除。

To support the development and growth of more high-quality educational tools, SECTL organization now opens channels for new projects to join and provides the following support and benefits for eligible projects. This document aims to clarify the cooperation framework, protect the rights and interests of both parties, and promote the joint development of projects and the organization.

I. Application Instructions

  • Application Channel: To apply for joining the organization or applying for a second-level domain, please contact the SECTL group owner (QQ: 3267139343) with basic project information (such as name,定位,功能简介,开源/闭源情况,项目链接等) for review;
  • Review Criteria: With "serving educational scenarios" as the core, the project practicality, stability, and ecosystem alignment will be comprehensively evaluated.

II. Internal Collaboration Channels (Feishu)

The organization has set up Feishu internal groups for official member projects, used for:

  • Project progress synchronization and problem discussion;
  • Sharing organization internal materials and development resources;
  • Collaborating on publicity and activity planning.

Only core members of projects that have joined the organization can join. The entry method will be notified separately by the group owner (QQ: 3267139343) after the review is approved.

III. Core Support Content

  1. Dedicated Documentation Site Second-Level Domain Support

    All projects that officially join the organization can use the second-level domain provided by SECTL to build a dedicated documentation site (format: "[project identifier].sectl.top", for example, if the project name is "SecRandom", the documentation site domain is "secrandom.sectl.top"). The organization will assist in completing domain resolution and basic configuration, reducing project documentation maintenance costs and improving user access convenience.

  2. Multi-dimensional Publicity Resource Support

    The organization will promote projects through the following channels:

    • Official Community: Publish project dynamics, feature highlights, and use cases through QQ group 833875216;
    • Video Platform: Publish project introductions and operation demos on the official Bilibili account to expand the reach to educational scenario users;
    • Feishu Platform: Publish project updates, usage tips, and educational scenario application solutions through the organization's official Feishu account/groups, facilitating institutions and teacher groups to quickly obtain information.

IV. Special Agreements for Open Source Projects

For open source projects, after joining the organization, the project repository must be moved directly to the SECTL official GitHub organization (address: https://github.com/SECTL), not using the Fork method. After the move is completed, the original repository can be set as a mirror or archived, but must retain the jump instruction to the new repository to ensure users and the community can correctly access the latest code.

V. Publicity and Long-term Cooperation Evaluation

  • Publicity Schedule: The organization's unified publicity is fixed to be carried out on the anniversary of the organization's establishment each year (specific dates subject to the announcement of the current year);
  • Video Publishing Rules: During the project membership period in the organization, regardless of whether the video is produced uniformly by the organization or independently by the project developer, it must be published through the SECTL organization's official Bilibili account;
  • Long-term Cooperation Evaluation: In addition to "continuous participation for 1 year", it is necessary to comprehensively evaluate the actual value of the project to educational scenarios (such as user coverage, feature iteration quality, community contribution, etc.) to ensure cooperation quality.

VI. Long-term Cooperation Incentives

Additional incentive policies are set for high-quality projects planning to establish long-term stable cooperation with the organization:

  • Cooperation Duration Requirement: From the date of joining, continuously participate in organization affairs and have not voluntarily withdrawn for 1 year;
  • Project Attribute Requirements: Must comply with the organization's core positioning of "serving educational scenarios" (such as teaching tools, class management, student services, etc.);
  • Incentive Forms: Based on the project's actual contribution (such as user feedback, feature iteration, community activity, etc.), the organization will provide corresponding bonus support after evaluation (specific amount to be discussed on a case-by-case basis).

VII. Exit Mechanism and Post-processing

If a project needs to exit the organization for special reasons, the following agreements must be observed:

  1. Advance Application: Exit requires submitting a written application to the group owner (QQ: 3267139343) two weeks in advance;
  2. Written Application Content Requirements: The application must include:
    • Project name and project identifier;
    • Date of joining the organization;
    • Exit reason (can be brief);
    • Project leader contact information (QQ/Email);
    • Confirmation that they have understood and agreed to the terms such as time reset and information labeling after exit;
  3. Time Reset: Upon exit, the project's "continuous cooperation duration" in the organization will automatically reset, and re-joining will require recalculating the cooperation cycle;
  4. Information Labeling Obligations:
    • The project must note in the README file at the bottom of its repository: "This project joined SECTL organization from XX/XX/XXXX to XX/XX/XXXX, relevant information is subject to the organization's historical announcements";
    • For open source projects, the organization affiliation description (e.g., "Formerly part of SECTL organization") must also be retained in the README;
  5. Historical Publicity Instructions: For Bilibili promotional videos published by the organization that involve exited projects, a top comment will be added (e.g., "Note: Project [XXX] exited SECTL organization in XX/XXXX, current status is subject to the project's latest information");
  6. Feishu Exit: After exiting the organization, project-related members must simultaneously exit the SECTL Feishu internal group and no longer retain member status;
  7. GitHub Organization Exit: For open source projects, upon exit, the project repository must be moved out of the SECTL official GitHub organization (https://github.com/SECTL), can be managed independently or transferred to other accounts/organizations, and the original repository's jump instructions must be updated or removed simultaneously.
